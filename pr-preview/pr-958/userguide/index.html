User Guide¶

This guide is for the developers who change the GitHub organizations and repositories of their project through an existing otterdog setup: the day-to-day path from a need to a change applied on GitHub. To install and operate otterdog itself, see Operating Otterdog.

Learn the workflow

How a change goes from a pull request to GitHub, see Workflow for changes.

Find your guide

Start from your need in the Configuration Guides.

Try it

Edit and check your change in the Playground of the dashboard.

Propose it

Open the pull request, otterdog validates and applies it.

Making changes¶

Every change to the configuration of an organization is a pull request on its configuration repository.

  • Workflow for changes

    From the Playground or a branch to the changes applied on GitHub: the validation, the review, the auto-merge with /otterdog merge and the apply.

  • Adding, renaming and removing resources

    Declare a new resource with the function of the default configuration, rename a repository or a webhook without deleting it, delete a resource.

Configuration Guides¶

The Configuration Guides start from common needs and explain how to address them with otterdog, including the trade-offs and limitations to consider. Every property is documented in the Reference.

  • Security and automation

    Securing GitHub Actions · Repository security features · Secrets and variables · Deployment environments · Webhooks

  • Organization and access

    Organization settings and member privileges · Teams and access

  • Repositories

New to otterdog?

When something goes wrong¶

  • Troubleshooting

    Understand a message of the validation, a reply of /otterdog merge, or an unexpected result of plan and apply.
